# prorab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 11–12 additionally follow superpowers:writing-skills (RED → GREEN → REFACTOR with pressure scenarios).

**Goal:** A Claude Code skill `prorab` that lets one session (прораб) run Claude brigades in herdr panes across projects for hours unattended, with наряды in beads, acceptance by evidence, context/limit/budget control, handovers and a morning report.

**Architecture:** A lean Russian `SKILL.md` holds the rules; all mechanics live in small stdlib-Python scripts under `prorab/scripts/` (one responsibility each) that wrap the `herdr` and `bd` CLIs and read Claude transcripts. All numbers (thresholds, budget, context windows) live in one file, `prorab/references/defaults.json`. State lives in the прорабская's own beads database.

**Tech Stack:** Python 3 standard library only (`unittest` for tests), POSIX sh for the statusline tap, herdr ≥ 0.9.5, bd ≥ 1.3 (embedded Dolt), Claude Code 2.1.x, superpowers plugin (recommended, with fallback).

**Spec:** `docs/superpowers/specs/2026-10-21-prorab-design.md` (approved 2026-10-21). Read it before any task; this plan argues from it.

## Global Constraints

- Required: herdr ≥ 0.9.5 with `HERDR_ENV=1`, bd ≥ 1.3. Nothing else is installed. No beads in objects is ever initialised or edited by prorab.
- Python: standard library only; no pip, no uv, no third-party modules. Scripts start with `#!/usr/bin/env python3` and import siblings from `prorab/scripts/` (add `os.path.dirname(__file__)` to `sys.path`).
- Brigades are Claude only (`--kind claude`). Codex is never started as a brigade.
- Journal: `BEADS_DIR=~/projects/prorab/.beads` for every `bd` call made by prorab. `.beads/` is in the repo `.gitignore`.
- No customer data in `prorab/` or `docs/`: no names of the customer's projects, no paths to them, no client data, no quotes from real sessions, no names of personal tools. Examples, fixtures and scenarios are synthetic and neutral only (e.g. `demo-app`, `/home/user/projects/demo-app`). Guarded by `prorab/tests/test_no_private_data.py`.
- Language: `SKILL.md`, `references/*.md`, наряды, acts and reports in Russian; code, identifiers, tests, commit messages in English.
- Thresholds (copy into `defaults.json` verbatim): context soft = min(60 % of window, 500 000 tokens); context hard = 80 % of window; 5h day: 60 % no new mass runs, 80 % stop after current step and wait for reset; 5h night (night shift only): window that resets before the morning → stop at 95 % (no separate no-new-mass threshold), window that covers the morning → 70 % no new mass runs, 80 % stop (≥ 20 % left by morning), reset time unknown → day thresholds; morning `night.morning` = `08:00`; week: 50 % notify, 70 % only наряды with допуск; unknown model window = 200 000; Opus 5.5 (`claude-opus-5-5`) window = 1 000 000.
- Budget defaults per shift: 30 brigade sessions, 200 agent runs spawned by brigades, +10 percentage points of weekly Claude Max; no fixed brigade count — the prorab computes it as the minimum of ready tasks, the limit bound, the machine-load bound and `parallel_ceiling` = 6; several brigades on one object only when their file lists are disjoint; `heavy_slots` = 2 heavy runs machine-wide; default task estimate 30 min.
- «игнорируй лимиты и закончи» (customer's words only; kv `override.ignore_limits`) lifts the 5h/week thresholds and the shift budget until the current goal is done; it never lifts ТБ (consent prompts, push, PR, release, merge to main) or machine protection (load bound, heavy slots, `parallel_ceiling`).
- Limits from idle sessions are stale (Claude Code shows the last API response of THAT session; the countdown keeps running, the percent freezes): per window take the MAXIMUM over all panes / fresh per-session sensor files of the latest `resets_at`; a pane whose countdown shows `(0m)` belongs to the previous window and is ignored for it; an unknown week is `None`, never 0; unknown for > 30 min → `blind_week`; at night an unknown week means no new mass runs (Amendment L).
- Monitor heartbeat 20 min; brigade "hung" = `working` with no transcript growth for 30 min; max 2 restarts per наряд.
- Never: answer a trust/consent prompt, push, open a PR, release, merge to main, exceed the budget, use `nohup`, delete a worktree with unmerged commits.
- Tests must never touch the real `~/.claude/settings.json`, the real `~/projects/prorab/.beads`, or real herdr panes; they use temp dirs, a temp `HOME`, and the fake `herdr` stub. Only Task 13 touches real herdr/Claude.

## Review Focus

1. **No limit source at all** (clean install, no sensor, narrow panes): the monitor must report `blind` once, then stay quiet after the prorab acknowledges it (`kv limits.blind_ack`) — not wake the prorab every 90 s forever. Test in Task 7.
2. **Brigade `idle` while background shells run** ("N shell" in its status line): not a stop point, no handover. Test in Task 4 (`bg_shells`) and Task 7 (`settled` suppressed).
3. **A brigade waiting in a multiple-choice dialog** (`blocked`, but not a consent prompt): the prorab reads the options and answers within the наряд; a consent prompt (trust, `.mcp.json`) is never answered. Test in Task 4 (`choice_dialog`) and Task 6 (`answer`). The stale-sensor case stays covered by Task 3's `test_sensor_stale_falls_through`.
4. **Prompt lost after startup** (`agent_prompt_stalled`): `send` returns `stalled`, never reports success; `timeout` with status `working` afterwards counts as accepted. Test in Task 4.
5. **A second prorab** started while one is alive: refuses (`acquire_active` false); a dead one's lock (pane gone from `herdr agent list`) is taken over. Test in Task 5.
6. **Night reserve**: night shift, 05:30, window at 78 % resetting at 10:00, 4 more tasks ready → no new mass runs (≥ 70), stop at 80, ≥ 20 % left at 08:00; unknown reset time at night → day thresholds. Test in Task 6b (`cap_for`) and Task 7 (`limit` uses `cap_for`).
7. **«игнорируй лимиты и закончи»**: no `limit`/`smeta` events while it holds, readings still logged; machine protection still bounds `allowed_parallel`; it expires when every наряд of the goal is accepted or waiting for the customer. Test in Tasks 5, 6b, 7.
8. **Stale limits from idle panes** (Amendment L): two panes 17.0 % (idle) and 28.0 % → 28; a `(0m)` pane at 70 % plus a fresh 5 % → 5; narrow panes only → week `None`; context = the first bar of the status line, not the last percent. Test in Task 3 (follow-up commit), Task 7 (`blind_week`), Task 8 (per-session files).
